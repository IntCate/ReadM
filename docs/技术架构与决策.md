# 技术架构与决策

版本 v0.1。当前仅 Web；未来客户端是明确需求。第一阶段技术栈已实现并通过锁文件固定，实际验证证据见 [第一阶段实现与验证](第一阶段实现与验证.md)；后续平台与 MIDI 仍为设计。

## 分层与依赖

```text
apps/web（React UI、组合根、模式控制）
 ├─ editor-core → score-core
 ├─ notation-staff / notation-jianpu → score-core
 ├─ playback → score-core
 ├─ midi-input → editor-core（通过命令接口）
 ├─ practice → score-core + 演奏计划/归一化事件类型
 └─ platform-web → 平台契约（MIDI、Audio、Clock、Repository、Files）
```

核心模块不得依赖 React、DOM、IndexedDB、navigator 或浏览器 MIDI 对象。渲染适配允许使用 SVG/DOM；业务操作只能经过编辑命令，不能直接修改 VexFlow 对象后反向猜测文档。app 负责注入平台实现，不让 core 导入 platform-web。初始目录按上述边界组织，是否拆为独立包由构建复杂度决定，不为未来端创建空壳。

## 模块契约

| 接口/模块 | 输入 | 输出/失败 | 责任 |
|---|---|---|---|
| ScoreValidator | 文档或导入结构 | 位置化错误列表 | 不变量与范围校验 |
| Editor | 文档、命令、revision | 原子新版本或错误 | 音乐规则、历史、脏区 |
| NotationLayout | 文档、宽度、视图偏好 | 布局片段、元素边界、命中索引 | 按拍对齐，不改变音乐语义 |
| PlaybackCompiler | 文档、revision、循环范围 | 有限 PlaybackPlan | 反复展开、tie 合并、速度换算 |
| MidiPort | 用户授权动作、设备选择 | 状态流、归一化事件流、取消订阅 | 平台事件边界，不直接写谱 |
| AudioEngine | 绝对音频时间、音高、力度、持续时长 | 可取消句柄、引擎状态 | 发声、停止全部声音、中断清理 |
| Clock | 音频/单调时钟采样 | 可失效映射和时间转换 | 不使用墙上时间评估节奏 |
| ProjectRepository | 快照、expectedRevision | 成功提交或冲突/配额错误 | 原子保存、恢复、单写者 |
| FileService | 用户选择/导出动作 | 字节或取消/错误 | 无外部路径假设 |
| PracticeEngine | 固定谱版本、目标计划、演奏事件 | 匹配、评分、置信度与当前位置 | 不操作 DOM、音频节点或仓储 |

## 工程决策记录

| 决策 | 当前结论 | 原因及重评条件 |
|---|---|---|
| ADR-01 | 三阶段只交付 Web，核心保留平台接口 | 用户明确范围；原生端启动时另建决策 |
| ADR-02 | React/TypeScript/Vite | 匹配 JS 乐谱生态；团队约束或原型证据可触发重评 |
| ADR-03 | 自有语义模型，VexFlow 与 SVG 简谱为视图 | 不能让展示库决定产品数据；原型验证编辑与布局性能 |
| ADR-04 | 第一阶段直接 Web Audio；第二阶段 Web MIDI | 当前使用谐波合成钢琴，不增加 Tone.js/远端采样依赖；音频适配接口可替换；硬件延迟仍需第二阶段实测 |
| ADR-05 | IndexedDB 本地优先，当前无业务后端 | 用户尚未提出账号/云同步；增加时须走需求变更 |
| ADR-06 | P3A/B 规则匹配，P3C 研究后决定 | 避免把自由跟随默认为基本练习门槛 |
| ADR-07 | 不把 OSMD/Verovio/MuseScore 引擎列入当前依赖 | 原型用 VexFlow 路线；旧研究只保留对照依据 |

ADR-02 至 ADR-07 的第一阶段部分已据原型采用，具体版本在 apps/web/package-lock.json，证据在实现记录；不代表用户逐项确认依赖或已验证后续 MIDI。当前目录采用 src/core、src/components、src/platform，按已定义边界组织，尚未拆为独立 npm 包。

## 性能与失效

布局按小节缓存，但节拍列跨双手，修改任一手必须重新计算该小节的双手公共列及受宽度变化影响的后续系统。光标和选区单独覆盖层，播放不能整谱重排。必要时将纯布局或编译移入 Worker；先测量再引入，Worker 不负责 AudioContext/DOM。

编译与布局结果带 revision；异步旧结果返回时丢弃。UI 模式由一个协调器控制，停止时统一取消音频队列、订阅和计时器；每次 session 使用独立 token 防止旧回调污染新会话。

## 未来扩展

未来桌面/移动客户端实现同一平台契约；时间戳与文件格式保持明确单位和版本。是否复用 React UI、采用何种壳、原生采样器或 FFI，届时另行验证。当前不编写原生插件、不承诺零改动迁移。

依赖依据及许可研究保留在 [调研快照](research/2026-10-18-初步调研快照.md)。生产构建只能使用锁定版本和许可清单中的依赖，不以动态分支网页代替实际包审查。
