# 开发与发布计划

版本 v0.1。第一阶段代码已实现并进入本地验证；下表保留原工作包规划，不代表所有任务仍未开始或全部验收完成。实际结果见 [第一阶段实现与验证](第一阶段实现与验证.md)。后续日历和人月仍不沿用旧多端估算。

## 里程碑

| 里程碑 | 目标与入口 | 出口 |
|---|---|---|
| M0 文档和技术验证 | 从当前文档开始；Q-01/02 可带明确假设验证 | 双手双谱编辑原型、浏览器 MIDI/音频测量、代表样谱；关闭影响 P1 的待决策 |
| M1 P1 生产闭环 | M0 完成并冻结 P1 规格、依赖与目标环境 | 编辑→切谱→播放→保存恢复→项目交换；P1 用例及质量门槛通过 |
| M2 P2 MIDI | P1 稳定、Q-03/06 证据齐备 | 接入、监听、步进、固定速度录制量化通过 P2 验收 |
| M3 P3A/B 练习 | P2 稳定，Q-07 决定练习范围 | 等待/节奏、分手与报告，中断恢复通过 P3 验收 |
| M4 未来扩展 | 用户选择对应候选或启动原生端 | 独立需求变更、架构评估与计划，不占用当前必做任务 |

M0 建议时间盒 2–4 周，只是验证预算建议；逾期应记录结果与方案决定，不直接把原型变生产。M1–M3 暂无承诺日历。

## 单项开发准入

开始工作包前拆出可独立审查的子任务，包含需求 ID、前置条件、输入输出、不支持项、测试样例。完成一条“编辑右手和弦”就验证该行为，不新增只复述实现的测试。复杂音乐运算、数据恢复和匹配必须有可重放证据。

文档不能代替视觉原型：M0 补充大小调、双手和弦、6/8、长音对齐的视觉样例，完成音乐顾问与可用性评审后才冻结布局。

## 构建、发布与回滚

开发期锁定 Node/包管理器与运行依赖，提交 lockfile；流水线执行文档检查、类型检查、必要单元/集成测试、目标浏览器端到端测试和生产构建。具体版本由工程初始化时记录，不在无依赖文件时虚构。

发布为 HTTPS 静态应用，资源带内容哈希；入口页避免长期缓存旧版本。预发布环境先跑完整闭环。发布清单包括资源许可、兼容矩阵、已知限制和 schema 版本；MIDI 权限策略按实际域与嵌入方式验证。

生产版本出现数据风险时回滚静态构建，但不能假设旧代码能读新 schema：迁移先备份，旧版只读/拒绝处理新版本，必要时保留兼容的新版本修复。当前不实现完整离线启动缓存，已加载页面的本地操作与“断网可重新启动”需分别表述。
