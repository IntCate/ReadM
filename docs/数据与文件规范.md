# 数据与文件规范

版本 v0.1；本文定义字段、时间单位与持久化约束。运行时校验与真实项目样例已在 `apps/web/src/core/score.ts` 和 `apps/web/examples/` 实现，下表为字段合同，具体可执行类型以这些实现及回归证据交叉检查。

## 时间和身份

音乐时间统一用约分后的 Rational `{n: integer, d: positive integer}`，单位是四分音符。4/4 小节长度 4，6/8 长度 3，八分音符 1/2，八分三连音 1/3。使用安全整数并限制分母，比较使用有理数算法；不得用浮点相等判断是否满小节。

ID 为项目内唯一不透明字符串。复制生成新 ID，撤销恢复原 ID；布局片段允许多个 fragment 回指同一元素。演奏 occurrence ID 在每次编译内唯一，跨编译统计还需携带 revision 和演奏路径，不能仅靠数组下标。

## 实体和字段

| 实体 | 必须字段 | 规则 |
|---|---|---|
| ProjectEnvelope | format、schemaVersion、projectId、revision、updatedAt、score | format 固定为 piano-score-project；可选 sourceProjectId 保留导入来源；时间为 UTC ISO 字符串 |
| ScoreDocument | id、title、parts、measures、events、ties、slurs、tuplets、tempoMap、repeatRegions、notationPolicy | 不含像素坐标、AudioNode、MIDI 设备对象 |
| PianoPart | id、instrument=piano、staves、voices | P1 一架钢琴，两谱表 |
| Staff | id、defaultClef、defaultHand | 手别和谱表不是同一 ID |
| Voice | id、partId、defaultStaffId | 每个事件必须指向有效声部 |
| Measure | id、order、meter、key、minor、actualLength | key 为 -7 至 +7，minor 表示自然小调；actualLength 默认等于拍号推导长度；弱起显式缩短 |
| Event | id、measureId、staffId、voiceId、hand、onset、duration、kind、written、notes | hand 为 left/right；kind 为 chord/rest |
| Note | id、pitch、velocity? | pitch 为 step C–B、alter -1/0/1、octave；MIDI 键号由它派生 |
| WrittenValue | base、dots、tupletId? | base 用音符分母 1/2/4/8/16/32；dots 为 0/1 |
| Tie | id、fromNoteId、toNoteId | 相邻连续、同拼写和发声音高；跨拆分事件连接 |
| Slur | id、fromEventId、toEventId | 同乐句端点，不合并音频事件 |
| Tuplet | id、eventIds、actual、normal | P1 3:2；总实际时长必须闭合 |
| TempoPoint | measureId、onset、quarterBpm | P1 onset=0；BPM 总以四分音符为单位 |
| RepeatRegion | id、startMeasureId、endMeasureId、count | P1 非嵌套，count=2；编译必须有限 |
| NotationPolicy | jianpuMode、referencePitch | 例如 major-do/minor-la，基准八度策略随项目保存 |

和弦事件的 notes 非空；休止 notes 为空。相同和弦中每个音都有 Note ID，方便单音选中与延音。多声部结构先预留，但不因此宣称界面已支持同手复调。

## 最小字段示例

```json
{
  "id": "event-r1", "measureId": "m1", "staffId": "staff-r",
  "voiceId": "voice-r", "hand": "right", "onset": {"n": 0, "d": 1},
  "duration": {"n": 1, "d": 1}, "kind": "chord",
  "written": {"base": 4, "dots": 0},
  "notes": [{"id": "note-c4", "pitch": {"step": "C", "alter": 0, "octave": 4}}]
}
```

该示例仅为一个四分音符事件，不是完整可导入项目。

## 校验与编辑提交

事件满足 onset≥0、duration>0、onset+duration≤actualLength。同一声部内事件不重叠，并通过显式休止覆盖小节；和弦共享时值。两个声部同时演奏不属于重叠错误。written、dots、tuplet 推导出的时长必须等于 duration。

提交前校验所有引用、音域、时值、反复边界和连接。一个事务全部成功后才递增 revision；失败不改变原谱。派生 MIDI 键号与 pitch 不重复存为可独立修改的权威字段。

## 项目文件和自动保存

自有文件扩展名工作约定为 `.pianoscore.json`，UTF-8，无压缩、无脚本、无外部资源引用；扩展名不是格式识别的唯一依据。音色资源不嵌入文件。导入先按字节和实体数量限额校验，再验证 schema，生成新本地项目 ID，同时保存来源 ID，避免覆盖已有项目。

IndexedDB 以 projectId+revision 原子写入完整快照，另存最近已提交版本和恢复候选。默认修改后 1 秒防抖保存；连续编辑最长每 5 秒请求一次保存。只有事务提交成功才能显示 saved。卸载事件不是可靠保存机制，浏览器退出前可能丢失最后未提交修改，界面必须显示该状态并支持手动导出。

文档 revision 与视图偏好独立；原始录制和练习会话引用 projectId、revision 并保留所需谱快照，不受之后编辑污染。P2 原始 MIDI 记录与量化结果分开保存，P3 会话删除不删除乐谱。

## 迁移与不兼容

schemaVersion 是递增整数，首个实现从 1 开始。较新未知版本拒绝可编辑打开并允许下载原始文件；当前 schemaVersion=1，为首个已发行结构，尚无旧版迁移器；未来添加迁移时必须先备份，纯函数迁移、验证后另存，不原地覆盖失败文件。未知字段只能在明确的 extension 容器保留，不能绕过校验。

数据大小、最大实体数和 XML 解压限额由测试文档统一定义，运行时从同一配置读取。旧调研中的 MusicXML/MXL 与 MIDI 文件交换不是核心项目格式；待增强需求启用时实现独立适配器，生成 UnsupportedElement 报告，不能把格式转换器内部模型泄漏进核心。
