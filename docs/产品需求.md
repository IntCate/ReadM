# 产品需求

版本 v0.1。需求范围引用 [需求与追踪](需求与追踪.md)，确认状态不在本文重复定义。

## 定位与成功结果

服务使用钢琴和 MIDI 键盘的学习者、教师及轻量制谱者。核心闭环为：制作双手乐谱 → 五线谱/简谱编辑与切换 → 试听和修正 → 保存 → 键盘输入 → 针对同一份谱练习。

第一阶段成功意味着用户能独立制作含双手不同节奏、和弦、休止与跨小节延音的短谱，在两种视图修改任一只手并听到相同音乐结果，关闭页面后能恢复作品。不能以只有展示能力的简谱替代简谱编辑。

## 三阶段用户任务

| 阶段 | 用户任务 | 完成结果 | 详细规格 |
|---|---|---|---|
| P1 | 新建双手谱、选手与输入音符 | 两手语义独立且共享小节时间轴 | 交互、乐谱、编辑命令 |
| P1 | 切换记谱、选区修改与撤销 | 内容不丢失，选区定位稳定 | 交互、数据 |
| P1 | 试听、变速、循环、单手播放 | 声音及光标跟随实际演奏顺序 | 播放与MIDI |
| P1 | 保存、恢复、项目交换 | 明确区分内存修改与成功落盘 | 数据、交互 |
| P2 | 接键盘弹奏、步进打谱 | 设备状态清晰、发声可关闭、录入可撤销 | 播放与MIDI、编辑命令 |
| P2 | 固定速度录制、预览量化 | 原始事件保留，用户确认后写入乐谱 | 播放与MIDI |
| P3 | 分手/双手、分段练习 | 得到可解释的音高与节奏反馈 | 练习与评分 |

## 范围控制

第一阶段的必要音乐能力以 [乐谱与简谱规格](乐谱与简谱规格.md)的支持表为准。每手单一节奏声部是待评审的工作边界，不代表已获用户同意排除同手复调；该项必须在谱例评审后冻结。左右手内的和弦和两手不同节奏不受此待决策项影响。

MusicXML/MXL 交换、MIDI 文件导出、打印/PDF 是建议的增强项；当前核心验收只强制自有项目文件导入导出。不得从调研报告中的“必须交付”文字推导它们已经被用户确认。完整离线启动、PWA 安装、账号同步、公开曲库、商业化、多人协作、扫描识谱和音频转谱均不属于当前实施基线。自由跟随保留为 P3C 候选，不作为基本跟谱练习的隐含承诺。

## 产品质量

数据不静默丢失；错误有明确恢复路径；不支持的音乐内容不得被转换成看似成功但缺音的谱。音乐语义一致优先于两个视图视觉相同。Web 硬件能力不可用时，说明原因并保留实际可用的手动编辑功能。

首轮用户验证观察完成 8 小节双手谱所需时间、求助次数、切谱后修正次数及练习反馈误判。先记录基线再设改进目标，不虚构活跃用户和留存指标。

## 当前界面与部署假设

先以桌面浏览器键鼠工作台为目标；中文界面、单钢琴音色、本地项目管理为工程默认。品牌、收费、云服务与移动交互未确定，不生成相关业务实现。未来客户端通过架构中的平台接口演进。
